# Senior Backend Competencies

Senior scope is defined by decisions and outcomes, not by syntax speed.

| Competency | Observable behavior |
|---|---|
| Problem framing | Clarifies users, invariants, constraints, and non-goals before designing. |
| Technical judgment | Compares alternatives and chooses the least complexity that satisfies known needs. |
| Data integrity | Defines ownership, transaction boundaries, concurrency behavior, and recovery. |
| Reliability | Designs for timeouts, overload, partial failure, retries, and safe degradation. |
| Operability | Makes state visible through useful logs, metrics, traces, health signals, and runbooks. |
| Security | Uses threat modeling, least privilege, safe defaults, and auditable controls. |
| Performance | Measures end-to-end behavior and optimizes verified bottlenecks. |
| Delivery | Breaks risky work into reversible steps and validates changes in production. |
| Collaboration | Writes clear proposals, gives actionable reviews, and grows other engineers. |
| Ownership | Follows problems through incidents, learning, and prevention. |

For every project, collect evidence in at least six rows. A feature alone is weaker evidence than a decision, experiment, incident drill, or explanation.
